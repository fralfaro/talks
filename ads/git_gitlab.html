¿Qué es Git?



git


historial
del proyecto


  • Guarda versiones de tus archivos.

  • git status: muestra el estado.
  • git add: selecciona cambios.
  • git commit: guarda una versión.
  • git log: muestra el historial.

Estándares Git

Ramas, commits, versiones y repos limpios

Convenciones de ramas


Tipo de rama Para qué sirve Ejemplo
feature/ Nueva funcionalidad feature/login-oauth
bugfix/ Corrección en desarrollo bugfix/error-formulario
hotfix/ Corrección urgente hotfix/error-pago
release/ Preparar versión estable release/v1.2.0
chore/ Mantención o cambios menores chore/actualizar-dependencias


Usa minúsculas, guiones y nombres cortos. Mejor feature/descarga-pdf que feature/nueva funcionalidad final.

Trabajar con una rama



git switch -c feature/12-readme

# editar README.md

git add README.md
git commit -m "docs: actualiza README del proyecto"
git push -u origin feature/12-readme


  • La rama separa el trabajo en progreso.
  • El número puede vincularse a un Issue.
  • El push publica la rama para revisión.

Conflictos



Ocurren cuando Git no puede decidir cómo combinar cambios.


  1. Revisar con git status.
  2. Editar el archivo.
  3. Eliminar marcadores.
  4. git add.
  5. git commit o git rebase --continue.

GitLab

Subir el proyecto y colaborar

¿Qué es GitLab?



GitLab


repositorio
remoto
del equipo


  • Guarda una copia remota del repositorio.
  • Permite ver archivos, commits y ramas desde el navegador.
  • Gestiona permisos de integrantes.
  • Permite revisar cambios con Merge Requests.
  • Puede ejecutar pruebas automáticas con CI/CD.

Crear repositorio en GitLab


  1. Entrar a la URL de GitLab del curso o institución.
  2. Iniciar sesión con la cuenta indicada.
  3. Crear proyecto: New project → Create blank project.
  4. Nombre sugerido: mi-primer-repo.
  5. Marcar Initialize repository with a README.
  6. Crear el proyecto.


Si no puedes crear proyectos, probablemente falta permiso en el grupo.

Conectar GitLab con VS Code



En GitLab:


  1. Click en Code.
  2. Copiar la URL del repositorio.
  3. Usar HTTPS o SSH según indique el curso.

En VS Code:


git clone <url-del-repo>
cd mi-primer-repo
code .

Merge Request



Un Merge Request es una propuesta para unir una rama con otra.


  • Muestra el cambio línea por línea.
  • Permite comentarios y sugerencias.
  • Pide revisión antes de integrar.
  • Deja registro de la decisión.
!14 Actualiza README del proyecto
---------------------------------
Source: feature/12-readme
Target: main

Autor: @ana
Reviewer: @juan

Closes #12

Crear un Merge Request simple


  1. Crear una rama: feature/tu-nombre.
  2. Editar README.md.
  3. Hacer commit y push de la rama.
  4. En GitLab, click en Create merge request.
  5. Revisar source y target.
  6. Escribir título y descripción.
  7. Asignar revisor.
  8. Crear el MR.

La IA sugiere.

Reglas del curso


  1. Nunca pegues credenciales, tokens ni archivos .env.
  2. Nunca hagas merge de código que no entiendes.
  3. Todo MR necesita revisión humana.
  4. Declara el uso de IA si ayudó a escribir o revisar código.
  5. La responsabilidad del código es del equipo.

Actividad final


  1. Verifica git --version y abre VS Code.
  2. Crea un repo mi-primer-repo en GitLab con README.md.
  3. Clónalo en VS Code.
  4. Edita el README y haz commit + push.
  5. Crea una rama feature/tu-nombre.
  6. Agrega una sección nueva al README.
  7. Sube la rama y abre un Merge Request.
  8. Pide revisión a un compañero.
