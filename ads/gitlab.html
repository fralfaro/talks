¿Qué es GitLab?



GitLab


tu proyecto
en la nube


  • Guarda una copia remota del repositorio.
  • Permite trabajar con otras personas.
  • Muestra archivos, commits y ramas en el navegador.
  • Permite revisar cambios antes de unirlos.

Entrar a GitLab


  1. Abre la URL de GitLab indicada por el curso.
  2. Entra con tu cuenta institucional o la cuenta asignada.
  3. Busca el grupo, curso o espacio de trabajo.
  4. Revisa si puedes crear proyectos.
  5. Si no puedes, pide permiso al responsable del grupo.


Si GitLab no carga fuera del campus, puede que necesites VPN.

Crear un repositorio


  1. Click en New project.
  2. Elige Create blank project.
  3. Nombre: mi-primer-repo.
  4. Visibilidad: la indicada por el curso.
  5. Marca Initialize repository with a README.
  6. Click en Create project.


mi-primer-repo

Agregar o editar el README


En GitLab, abre README.md y edítalo:

# Mi primer repo en GitLab

Este repositorio fue creado para practicar Git y GitLab.

## Integrante
- Tu nombre


Escribe un mensaje de commit y guarda el cambio.

Conectar con VS Code



En GitLab:


  1. Click en Code.
  2. Copia la URL del repositorio.
  3. Usa HTTPS o SSH según indique el curso.

En VS Code:


  1. Abre una carpeta de trabajo.
  2. Abre la terminal integrada.
  3. Ejecuta git clone.
  4. Abre la carpeta clonada.

Clonar el repositorio



git clone <url-del-repositorio>
cd mi-primer-repo
code .


  • clone descarga el proyecto.
  • La carpeta ya viene conectada a GitLab.
  • VS Code detecta Git automáticamente.

Hacer un cambio local


Edita el README.md desde VS Code:

## Objetivo

Aprender a conectar Git, GitLab y VS Code.


Luego revisa el estado:

git status

Guardar y subir cambios



git add README.md
git commit -m "Actualiza objetivo del repositorio"
git push


  • add selecciona el archivo.
  • commit guarda el cambio local.
  • push sube el cambio a GitLab.
  • Al refrescar GitLab, el cambio aparece en el navegador.

Crear una rama feature



git switch -c feature/agrega-presentacion

# editar README.md

git add README.md
git commit -m "Agrega seccion de presentacion"
git push -u origin feature/agrega-presentacion


  • Trabajamos en una rama separada.
  • GitLab detecta la rama nueva.
  • Desde ahí podemos abrir un Merge Request.

Crear un Merge Request


  1. En GitLab, entra al repositorio.
  2. GitLab suele mostrar un botón para crear MR desde la rama nueva.
  3. Source: feature/agrega-presentacion.
  4. Target: main.
  5. Escribe título y descripción breve.
  6. Asigna un revisor si corresponde.
  7. Crea el Merge Request.

Qué revisar en un MR simple


Autor

  • El cambio es pequeño.
  • El título se entiende.
  • La descripción explica qué hice.
  • No subí archivos innecesarios.

Revisor

  • El README se ve bien.
  • El cambio corresponde al objetivo.
  • No hay errores evidentes.
  • Se puede aprobar o comentar.

Flujo completo


Problemas típicos


Problema Qué revisar
No puedo entrar Cuenta, permisos o VPN
git clone falla URL correcta, internet, credenciales
git push falla Permisos o autenticación
VS Code no muestra cambios Abriste archivo suelto en vez de carpeta
No aparece el MR Revisa si hiciste push de la rama

Actividad final


  1. Crea un repositorio mi-primer-repo.
  2. Inicialízalo con README.md.
  3. Clónalo en VS Code.
  4. Edita el README y haz commit.
  5. Sube el cambio con push.
  6. Crea una rama feature/tu-nombre.
  7. Haz otro cambio y súbelo.
  8. Abre un Merge Request hacia main.

Resultado esperado


En GitLab deberías tener:


  • Un repositorio creado.
  • Un README.md editado.
  • Al menos dos commits.
  • Una rama feature/tu-nombre.
  • Un Merge Request abierto o fusionado.
